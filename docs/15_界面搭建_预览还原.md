# UI 预览界面搭建设计方案

> 基于 `XCFramwork/assets/resources/UI/Preview` 下的 UI 预览图，使用 `ResourceData/Sprites` 图片资源还原界面，并接入框架 `UIManager` 模块统一管理。

## 1. 背景与目标

- `Preview/` 目录下有 20 张预览图（1920×1080），其中 01~15 为游戏界面图，00/16/20 为组件总览图（不做还原）。
- `ResourceData/Sprites/` 下有完整的切图资源（按钮、图标、边框、弹窗、滑条、开关等 400+ 张）。
- 框架已有完整 UI 管理模块（`UIManager` + `BaseView` + `views.json` 分层管理），但项目中尚无任何 `.prefab` 文件，`views.json` 配置的路径均为空缺状态。
- 目标：以代码动态搭建 + 空壳 Prefab 的方式还原全部 15 个界面，通过 `UIManager.open()/close()` 管理打开/关闭与层级。

## 2. 界面清单与分层映射

`UIManager` 按渲染层管理视图：`PageLayer(z=10)` 承载全屏页面、`DialogLayer(z=20)` 承载弹窗、`ToastLayer/LoadingLayer/SystemLayer` 为系统层。

## 3. 技术方案对比与选型

| 对比项 | 方案 A：手写完整 Prefab JSON | 方案 B：空壳 Prefab + 代码动态搭建（选定） | 方案 C：纯代码注册视图（改框架） |
|---|---|---|---|
| 图片引用方式 | Prefab 内硬编码 SpriteFrame uuid | 代码按资源路径动态加载 | 按路径动态加载 |
| 图片 uuid 风险 | **高**：切图 meta 为 Unity 格式，Creator 打开会重新生成 meta 并分配新 uuid，引用全部失效 | **无**：路径稳定，不依赖 uuid | 无 |
| 脚本组件引用 | 需要脚本 uuid（完整格式，可行） | 同左 | 无需 |
| 布局还原精度 | 编辑器手工调整，脚本无法保证视觉还原 | 代码按 1920×1080 像素精确布点，可还原预览图 | 同左 |
| 对框架侵入 | 无 | 无 | **需修改 UIManager**，违背"用框架管理"目标 |
| 工作量/可维护性 | 极高（15 个多节点 prefab 手写 JSON） | 中（一个 UIBuilder 工具 + 15 个视图类） | 中 |
| 项目先例 | 无 | **有**：`ExampleSceneSetup.ts` 即纯代码搭建 UI 的既有惯例 | 无 |

**选型结论：方案 B。**
- Prefab 只保留"根节点 + UITransform + 视图组件"的空壳，满足 `UIManager.open()` 对 Prefab 的硬性要求（prefab 路径存在 + 根节点有 `BaseView` 组件）。
- 节点树、布局、图片绑定全部在视图类 `onLoad()` 中由代码构建，像素级对齐 1920×1080 预览图。
- 图片通过 `AssetService.loadSpriteFrame('resources', path)` 按路径异步加载（见 §8 配套修复）。

### 5.3 UIBuilder.ts — 节点构建工具

静态工具类，封装重复样板代码（参照 ExampleSceneSetup 既有写法并增强）：

```ts
UIBuilder.node(parent, name, x, y, w?, h?, anchorX?, anchorY?): Node
UIBuilder.sprite(parent, name, path, x, y, w?, h?): Sprite          // 带异步资源绑定
UIBuilder.solidSprite(parent, name, color, x, y, w?, h?): Sprite    // 纯色块（遮罩/底板）
UIBuilder.label(parent, name, text, x, y, fontSize, color, bold?): Label
UIBuilder.button(parent, name, x, y, w, h, onClick): Button         // SCALE 过渡
UIBuilder.hLayout(node, spacingX, alignment): Layout
UIBuilder.vLayout(node, spacingY): Layout
UIBuilder.fullscreenWidget(node): Widget
```

### 5.4 BaseDialog.ts — 弹窗公共壳

12 个弹窗中 10 个结构同构（遮罩 + 白色圆角面板 + 标题栏），抽象公共基类：

```ts
export abstract class BaseDialog extends BaseView {
  protected mask!: Node;        // 全屏半透明遮罩（BlockInputEvents）
  protected panel!: Node;       // 白色圆角弹窗面板
  protected buildDialogShell(opts: DialogShellOptions): void;  // 构建壳 + 标题栏
  protected buildHeader(iconPath, title, iconSize): void;      // 图标+标题+关闭按钮
}
```

- `onOpen` 时机：`buildDialogShell()` → `onOpen(data)` 子类填充内容。
- 弹出动画：面板 `scale 0.85 → 1.0`（tween 0.15s，BACK_OUT 缓动）。
- 特例：`LevelUpDialog`（全屏蓝底，无遮罩壳）、`MainMenuView/StageView/ItemShopView`（全屏页，直接继承 `BaseView`）、`PauseDialog/StageCompleteDialog`（标题用丝带而非标题栏，通过选项切换）。

## 8. 配套修复：AssetService.loadSpriteFrame 路径后缀

**问题（根因）**：Cocos Creator 3.x 中 SpriteFrame 是贴图（ImageAsset/Texture2D）的子资源，正确加载方式为 `resources.load('path/spriteFrame', SpriteFrame)`。现 `AssetService.loadAsset` 调用 `resources.load(path, onComplete)` 未带 `/spriteFrame` 子资源后缀，png 主资源加载结果为 `ImageAsset`，随后 `instanceof SpriteFrame` 校验必然失败（报"资源类型不匹配"）。

**修复**（仅 `loadSpriteFrame` 入口处规范化路径，不影响其它类型）：

```ts
loadSpriteFrame(bundleName: string, path: string): Promise<SpriteFrame> {
  const spriteFramePath = path.endsWith('/spriteFrame') ? path : `${path}/spriteFrame`;
  return this.loadAsset(bundleName, spriteFramePath, SpriteFrame);
}
```

## 9. Prefab 生成方案（uuid / meta 机制）

- 项目切图 meta 为 Unity 格式 → Creator 首次打开会重新导入并分配新 uuid，因此 **Prefab 内不引用任何图片 uuid**，图片一律运行时按路径加载。
- 脚本 meta 均为 Cocos 标准格式（如 `BaseView.ts.meta` uuid `7e2a10e9-...`），**Prefab 内以完整 uuid 引用脚本组件**（与 `ExampleScene.scene` 引用 `ExampleSceneSetup` 的方式一致）。
- 新增脚本同时手工生成 `.ts.meta`（自分配 uuid v4），Creator 打开时沿用该 uuid，保证 Prefab 引用不失效。
- 每个 Prefab 结构：`[cc.Prefab] → cc.Node(根, 1920×1080 或面板尺寸) + cc.UITransform + <视图脚本组件>`，共 4 个序列化对象，无其它依赖。
- Prefab 同时生成 `.meta`（`importer: prefab`）。

## 11. 风险与注意事项

| 风险 | 说明 | 缓解 |
|---|---|---|
| Prefab 格式容错 | 手写 Prefab JSON 若缺字段，Creator 可能告警 | 首次打开 Creator 时若报错，全选 Prefab 重新保存一次即可修复 |
| 图片 meta 重导入 | Creator 首次打开会为 400+ 张 Unity 格式 meta 的图片重新生成导入信息 | 无影响：代码按路径加载，不依赖 uuid |
| Label 字体 | BPreplayBold 为 otf 动态字体，Label 直接使用系统 fallback | 先用默认字体 + 加粗观感还原，后续可在主题常量统一切换 |
| Sprite 加载时序 | 异步加载，先布局后贴图 | `bindSprite` 内失败仅告警；布局用 UITransform 固定尺寸，不因图片缺失变形 |
| Toggle/Slider 行为 | 预览为静态还原，交互为最小演示 | 事件接口保留在视图类中，后续接 Gameplay 再扩展 |
