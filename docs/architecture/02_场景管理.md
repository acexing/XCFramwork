## 1. 模块职责

- 场景切换入口统一化
- 切换前后回调、加载遮罩、进度展示
- 防止短时间重复触发同一切换
- 切换失败时记录日志并回退到安全场景
- 进入场景时加载所需 Bundle，离开时根据引用策略释放资源

---

## 2. 接口定义

```typescript
export interface ISceneService {
  goto(sceneName: SceneName, data?: SceneData): Promise<void>;
  getCurrentScene(): SceneName;
  registerHook(sceneName: SceneName, hookType: SceneHookType, callback: SceneHookCallback): void;
  unregisterHook(sceneName: SceneName, hookType: SceneHookType, callback: SceneHookCallback): void;
}

export type SceneName = 'Boot' | 'Loading' | 'Main';

export interface SceneData {
  [key: string]: unknown;
}

export type SceneHookType = 'beforeEnter' | 'afterEnter' | 'beforeLeave' | 'afterLeave';

export type SceneHookCallback = (data?: SceneData) => void | Promise<void>;
```

## 3. 类结构设计

```

```

## 4. 场景切换流程

```
goto(sceneName, data)
│
├── 1. canSwitch 检查
│   ├── 正在切换中 → 拒绝并记录警告
│   ├── 目标场景与当前相同且在冷却期 → 拒绝
│   └── 通过 → 继续
│
├── 2. 执行 beforeLeave 钩子（当前场景）
│   └── 失败 → 记录日志，继续（不阻塞离开）
│
├── 3. 显示加载遮罩
│   └── 显示进度条 UI
│
├── 4. 执行 beforeEnter 钩子（目标场景）
│   └── 失败 → 记录日志，继续
│
├── 5. director.loadScene(sceneName)
│   ├── 成功 → 继续
│   └── 失败 → onSwitchFailed
│       ├── 记录错误日志
│       ├── 隐藏加载遮罩
│       └── 回退到安全场景（Boot）
│
├── 6. 执行 afterEnter 钩子（目标场景）
│   └── 传入 data
│
├── 7. 隐藏加载遮罩
│
├── 8. 执行 afterLeave 钩子（原场景）
│   └── 释放原场景资源（根据引用策略）
│
└── 9. 更新 currentScene、lastSwitchTime
```

## 5. 钩子机制设计

### 5.1 钩子类型说明

| 钩子类型 | 执行时机 | 典型用途 | 失败处理 |
|---------|---------|---------|---------|
| beforeLeave | 离开当前场景前 | 保存当前场景状态、停止动画 | 记录日志，不阻塞 |
| afterLeave | 离开当前场景后 | 释放资源、清理定时器 | 记录日志 |
| beforeEnter | 进入目标场景前 | 预加载资源、准备数据 | 记录日志，不阻塞 |
| afterEnter | 进入目标场景后 | 初始化场景UI、恢复状态 | 记录日志 |

### 5.2 钩子注册约定

- 钩子回调支持同步和异步（返回 Promise）
- 同一场景同一钩子类型可注册多个回调，按注册顺序执行
- 钩子应在场景对应的组件 `onLoad` 中注册，`onDestroy` 中注销
- 禁止在钩子中执行耗时操作（如大量资源加载），应在 beforeEnter 中预加载

## 6. 资源加载与释放策略

### 6.1 进入场景时

- beforeEnter 钩子中通过 AssetService 预加载该场景所需的 Bundle
- 如果 Bundle 未加载，director.loadScene 会自动触发加载
- 建议显式预加载以获得进度控制

### 6.2 离开场景时

- afterLeave 钩子中根据引用策略释放资源
- 引用策略选项：
  - `immediate`：立即释放离开场景的独占 Bundle
  - `deferred`：延迟释放（等待新场景加载完成后再释放）
  - `keep`：保留（如核心 UI Bundle 常驻）
- 默认策略：`deferred`，避免切换过程中出现资源缺失

### 6.3 场景与 Bundle 映射

```typescript
const SCENE_BUNDLE_MAP: Record<SceneName, string[]> = {
  Boot: ['core'],
  Loading: ['core', 'ui_common'],
  Main: ['core', 'ui_common', 'gameplay_base'],
};
```

## 7. 错误处理

| 场景 | 处理方式 |
|------|---------|
| 切换冷却期内重复触发 | 拒绝切换，记录 debug 日志 |
| director.loadScene 失败 | 记录 error 日志，回退到 Boot 场景 |
| 钩子回调抛出异常 | 记录 warn 日志，继续执行后续钩子 |
| 预加载 Bundle 失败 | 记录 error 日志，尝试继续切换（引擎可能自行加载） |

## 8. 使用示例

```typescript
// 在场景组件中注册钩子
onLoad() {
  sceneService.registerHook('Main', 'afterEnter', this.onMainSceneEnter.bind(this));
  sceneService.registerHook('Main', 'beforeLeave', this.onMainSceneLeave.bind(this));
}

onDestroy() {
  sceneService.unregisterHook('Main', 'afterEnter', this.onMainSceneEnter.bind(this));
  sceneService.unregisterHook('Main', 'beforeLeave', this.onMainSceneLeave.bind(this));
}

// 业务代码中切换场景
async function startGame() {
  await sceneService.goto('Main', { chapterId: 1 });
}
```

## 9. 实现注意事项

1. **仍以 Cocos `director` 为底层能力**，不重新实现场景系统
2. **业务层调用 `sceneService.goto('Main')`**，不要到处直接调用 `director.loadScene()`
3. **场景名使用枚举或字面量联合类型**，避免散落字符串
4. **加载遮罩由 UIManager 提供**，SceneService 不自己创建遮罩节点
5. **冷却时间默认 500ms**，防止快速点击导致多次切换
