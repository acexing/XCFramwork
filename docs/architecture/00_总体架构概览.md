> 版本：1.0
> 日期：2026-10-10
> 关联文档：[Cocos Creator 3跨平台游戏基础框架方案](../../Cocos_Creator_3跨平台游戏基础框架方案.md)

---

## 1. 架构分层

框架采用三层架构，自上而下依次为：

### 1.1 游戏业务层

- 主玩法、关卡、剧情、角色、图鉴、商店等业务模块
- 只能依赖应用服务层的接口，不能直接操作其他业务模块的内部节点
- 核心数据与玩法规则不直接引用 `Node`、`Component` 或具体 UI 控件

### 1.2 应用服务层

- GameFlow、UI、Audio、Asset、Save、Config、EventBus、Timer、Pool、Locale、Analytics、Platform、Debug
- 通过接口依赖基础与适配层
- 服务的初始化顺序必须显式定义，禁止依赖文件加载顺序或隐式全局变量

### 1.3 基础与适配层

- Cocos Adapter、Steam Adapter、Android Adapter、Storage Adapter、Logger、Error Handler
- 平台差异集中在此层，业务代码通过接口调用，不在业务代码里写平台判断

### 1.4 引擎层

- Cocos Creator Engine + Native

## 2. 依赖规则

| 规则编号 | 内容 | 违反后果 |
|---------|------|---------|
| D1 | 业务模块可依赖应用服务接口，不能直接操作其他业务模块内部节点 | 模块耦合，无法独立测试 |
| D2 | 核心数据与玩法规则不引用 `Node`、`Component` 或 UI 控件 | 逻辑层无法脱离场景运行 |
| D3 | 平台差异集中在 `platform/`，业务代码通过接口调用 | 平台分支散落，维护困难 |
| D4 | 服务初始化顺序显式定义，禁止隐式全局变量 | 初始化时序不确定，难以排查 |
| D5 | 事件只用于解耦通知；有返回值的操作使用方法调用 | 事件链难以追踪，数据流混乱 |
| D6 | 所有异步操作须有错误处理、超时/失败回退和日志 | 静默失败，用户无感知 |

## 4. 服务初始化顺序

```
1. Logger / ErrorHandler        ← 最先初始化，确保后续错误可记录
2. GameConfig / PlatformAdapter ← 读取平台信息与全局配置
3. ConfigService                ← 加载玩法配置表
4. SaveService                  ← 读取存档与执行迁移
5. AudioManager                 ← 初始化音频引擎与设置
6. AssetService / UIManager     ← 资源加载与UI框架就绪
7. LocalizationService          ← 加载语言文本
8. 业务模块                      ← 各业务系统初始化
9. 进入主场景                    ← 启动流程结束
```

---

## 5. 异步调用风格约定

- 所有资源加载、场景切换、存档、平台调用统一使用 `Promise` 风格
- 不混用 callback 和 Promise；内部需要 callback 的引擎 API 在服务层包装为 Promise
- 通过依赖注入或 ServiceRegistry 获取服务，不允许各模块随意创建重复管理器
