## 1. 模块职责

### GameBootstrap

- 启动时按顺序初始化基础服务
- 检查必要配置和版本
- 进入 Boot → Loading → Main 的启动流程
- 统一处理初始化失败，展示可理解的错误提示

### ServiceRegistry

- 提供服务的注册与获取入口
- 保证每个服务全局唯一实例
- 支持按接口类型获取服务实例，实现依赖反转

## 2. 接口定义

```typescript
// ServiceRegistry 接口
export interface IServiceRegistry {
  register<T>(interfaceToken: string, instance: T): void;
  get<T>(interfaceToken: string): T;
  has(interfaceToken: string): boolean;
  unregister(interfaceToken: string): void;
}

// GameBootstrap 接口
export interface IGameBootstrap {
  run(): Promise<void>;
  getInitProgress(): number;
  isReady(): boolean;
}
```

## 3. 类结构设计

### 3.1 ServiceRegistry

```
ServiceRegistry
├── private services: Map<string, any>    ← 服务实例存储
├── register<T>(token, instance): void    ← 注册服务
├── get<T>(token): T                      ← 获取服务
├── has(token): boolean                   ← 检查服务是否存在
├── unregister(token): void               ← 注销服务
└── clear(): void                         ← 清空所有服务（测试用）
```

**设计要点：**
- 使用字符串 token 作为接口标识，避免直接依赖具体类
- token 建议使用常量定义，集中管理
- 注册时检查重复注册，开发版给出警告

### 3.2 GameBootstrap

```
GameBootstrap
├── private registry: IServiceRegistry
├── private initSteps: InitStep[]         ← 初始化步骤列表
├── private currentStep: number           ← 当前步骤索引
├── private _isReady: boolean             ← 是否完成初始化
│
├── run(): Promise<void>                  ← 执行启动流程
├── private initStep(step): Promise<void> ← 执行单个初始化步骤
├── private onInitFailed(error): void     ← 初始化失败处理
├── getInitProgress(): number             ← 获取初始化进度（0~1）
├── isReady(): boolean                    ← 是否完成初始化
└── private enterMainScene(): Promise<void> ← 进入主场景
```

**InitStep 结构：**
```typescript
interface InitStep {
  name: string;           // 步骤名称
  weight: number;         // 进度权重
  execute: () => Promise<void>;  // 执行函数
  isCritical: boolean;    // 是否关键步骤（失败则中止）
}
```

## 4. 启动流程详细设计

### 4.1 初始化步骤序列

| 顺序 | 步骤 | 权重 | 关键 | 说明 |
|------|------|------|------|------|
| 1 | Logger / ErrorHandler | 5 | 是 | 最先初始化，确保后续错误可记录 |
| 2 | GameConfig | 5 | 是 | 读取全局配置（版本号、平台信息） |
| 3 | PlatformAdapter | 5 | 是 | 识别当前平台，初始化对应适配器 |
| 4 | ConfigService | 10 | 是 | 加载玩法配置表，校验必填字段 |
| 5 | SaveService | 10 | 是 | 读取存档，执行版本迁移 |
| 6 | AudioManager | 5 | 否 | 初始化音频引擎，加载音频设置 |
| 7 | AssetService | 10 | 是 | 初始化资源管理，预加载核心 Bundle |
| 8 | UIManager | 5 | 是 | 初始化UI框架，创建UI根节点 |
| 9 | LocalizationService | 5 | 否 | 加载当前语言文本表 |
| 10 | 业务模块 | 20 | 否 | 各业务系统初始化 |
| 11 | 进入主场景 | 20 | 是 | 切换到 Main 场景 |

### 4.2 错误处理策略

```
初始化步骤执行
├── 成功 → 继续下一步骤
├── 失败 + isCritical=true
│   ├── 显示错误弹窗（包含模块名、错误摘要）
│   ├── 记录详细日志
│   └── 中止启动流程，等待用户操作
├── 失败 + isCritical=false
│   ├── 记录警告日志
│   ├── 该服务标记为不可用
│   └── 继续下一步骤
└── 所有步骤完成
    ├── 全部成功 → 进入主场景
    └── 存在非关键失败 → 进入主场景（降级模式）
```

### 4.3 进度展示

- Boot 场景中显示初始化进度条
- 进度 = 已完成步骤权重总和 / 总权重
- 每个步骤开始时更新进度文字（如"正在加载配置..."）

## 5. ServiceRegistry 使用约定

### 5.1 Token 定义

```typescript
// core/interfaces/ServiceTokens.ts
export const SERVICE_TOKENS = {
  Logger: 'ILogger',
  ErrorHandler: 'IErrorHandler',
  GameConfig: 'IGameConfig',
  PlatformService: 'IPlatformService',
  ConfigService: 'IConfigService',
  SaveService: 'ISaveService',
  AudioManager: 'IAudioManager',
  AssetService: 'IAssetService',
  UIManager: 'IUIManager',
  LocalizationService: 'ILocalizationService',
  EventBus: 'IEventBus',
  TimerManager: 'ITimerManager',
  PoolManager: 'IPoolManager',
  SceneService: 'ISceneService',
} as const;
```

### 5.2 服务获取方式

```typescript
// 正确：通过 ServiceRegistry 获取
const saveService = ServiceRegistry.get<ISaveService>(SERVICE_TOKENS.SaveService);

// 错误：直接 import 具体实现
import { SaveService } from './services/SaveService'; // 禁止在业务层这样做
```

### 5.3 服务注册时机

- 每个服务在自己的初始化步骤中创建实例并注册
- 注册完成后才可被其他服务获取
- 禁止在构造函数中依赖其他服务；依赖在 `init()` 方法中获取

## 6. 与其他模块的关系

| 关系 | 说明 |
|------|------|
| GameBootstrap → 所有服务 | 按顺序创建并初始化每个服务 |
| ServiceRegistry → 所有服务 | 提供服务的注册与查找 |
| 业务模块 → ServiceRegistry | 通过 token 获取所需服务接口 |
| 服务之间 → ServiceRegistry | 服务间依赖也通过 Registry 获取，不在构造时注入 |

---

## 7. 实现注意事项

1. **不要把所有功能写在 GameManager 单例里**：Bootstrap 只负责编排，具体功能由独立服务负责
2. **初始化步骤可配置**：允许根据项目需求增减步骤，但关键步骤不可跳过
3. **Boot 场景最小化**：Boot 场景只包含进度条和错误提示，不加载业务资源
4. **测试友好**：ServiceRegistry 支持 clear() 和 unregister()，便于单元测试隔离
5. **版本检查**：在 GameConfig 步骤中检查引擎版本和资源配置版本，不匹配时给出明确提示
