## 1. 模块职责

- 加载和管理静态玩法配置（关卡、商品、奖励、角色、剧情节点）
- 加载 UI 配置（界面路径、弹窗类型）
- 加载平台配置（能力开关、版本信息）
- 加载本地化文本（按语言拆分）
- 配置加载时校验必填字段、唯一 ID、引用是否存在
- 配置 ID 稳定，不依赖数组下标
- 配置表与运行时状态分离

## 2. 接口定义

```typescript
export interface IConfigService {
  loadConfig(configName: string): Promise<void>;
  getConfig<T>(configName: string): T;
  getConfigById<T>(configName: string, id: string): T | null;
  getAllConfig<T>(configName: string): T[];
  isLoaded(configName: string): boolean;
  validateAll(): ValidationResult[];
}

export interface ValidationResult {
  configName: string;
  isValid: boolean;
  errors: ConfigError[];
}

export interface ConfigError {
  type: 'missing_field' | 'duplicate_id' | 'invalid_reference' | 'invalid_type';
  field: string;
  id?: string;
  message: string;
}
```

## 3. 类结构设计

```
ConfigService
├── private configs: Map<string, ConfigRecord>     ← 已加载的配置
├── private configSchemas: Map<string, ConfigSchema> ← 配置结构定义
├── private loadingConfigs: Map<string, Promise<void>> ← 正在加载的配置
│
├── loadConfig(configName): Promise<void>
├── getConfig<T>(configName): T
├── getConfigById<T>(configName, id): T | null
├── getAllConfig<T>(configName): T[]
├── isLoaded(configName): boolean
├── validateAll(): ValidationResult[]
│
├── private loadFromBundle(configName): Promise<JsonAsset>
├── private parseConfig(json): unknown
├── private validateConfig(configName, data): ValidationResult
├── private buildIndex(configName, data): void
└── private registerSchema(configName, schema): void
```

**ConfigRecord 结构：**
```typescript
interface ConfigRecord {
  name: string;
  data: unknown;           // 原始配置数据
  index: Map<string, unknown>; // ID → 配置项的索引
  loadedAt: number;
}
```

## 4. 配置类别

### 4.1 静态玩法配置

| 配置名 | 内容 | 格式 | 加载时机 |
|--------|------|------|---------|
| levels | 关卡定义（ID、难度、奖励、解锁条件） | JSON | 进入主场景前 |
| items | 物品定义（ID、名称、类型、属性） | JSON | 进入主场景前 |
| characters | 角色定义（ID、属性、技能） | JSON | 进入主场景前 |
| shop | 商品定义（ID、价格、内容、限购） | JSON | 进入商店前 |
| story | 剧情节点定义（ID、触发条件、分支） | JSON | 进入剧情前 |
| achievements | 成就定义（ID、条件、奖励） | JSON | 进入主场景前 |

### 4.2 UI 配置

| 配置名 | 内容 | 格式 | 加载时机 |
|--------|------|------|---------|
| views | 视图定义（ID、Prefab路径、类型、缓存策略） | JSON | 启动时 |
| ui_layout | UI布局参数 | JSON | 启动时 |

### 4.3 平台配置

| 配置名 | 内容 | 格式 | 加载时机 |
|--------|------|------|---------|
| platform | 平台能力开关、版本信息 | JSON | 启动时 |

### 4.4 本地化文本

| 配置名 | 内容 | 格式 | 加载时机 |
|--------|------|------|---------|
| localization_zh | 中文文本表 | JSON | 启动时 |

```json
    {

      "type": "currency",

      "icon": "icons/gem"
    }
  ]

```

### 5.2 配置 Schema 定义

```typescript
interface ConfigSchema {
  name: string;
  version: number;
  fields: SchemaField[];
  idField: string;         // 主键字段名
  references: SchemaReference[]; // 引用其他配置的字段
}

interface SchemaField {
  name: string;
  type: 'string' | 'number' | 'boolean' | 'array' | 'object';
  required: boolean;
  defaultValue?: unknown;
}

interface SchemaReference {
  field: string;
  refConfig: string;
  refField: string;
}
```

## 6. 配置校验规则

### 6.1 必填字段校验

- 每个配置项的 required 字段必须存在且非 null/undefined
- 缺失必填字段时记录 `missing_field` 错误

### 6.2 唯一 ID 校验

- 配置项的 idField 必须唯一
- 重复 ID 时记录 `duplicate_id` 错误

### 6.3 引用完整性校验

- 配置中的引用字段必须指向目标配置中存在的 ID
- 引用不存在时记录 `invalid_reference` 错误

### 6.4 类型校验

- 字段值类型必须与 Schema 定义一致
- 类型不匹配时记录 `invalid_type` 错误

### 6.5 校验时机

- 配置加载完成后立即校验
- 开发版：校验失败时打印详细错误，阻止启动
- 发布版：校验失败时记录日志，尝试继续运行（降级）

## 7. 配置与运行时状态分离

```typescript
// 正确：配置只读，运行时状态独立管理
const itemConfig = configService.getConfigById<ItemConfig>('items', 'item_001');
const playerItem = playerData.getItem('item_001'); // 运行时状态

// 错误：直接修改配置对象
itemConfig.maxStack = 100; // 禁止！配置对象不可变
```

- 配置对象在加载后冻结（`Object.freeze`），防止意外修改
- 运行时状态由业务模块自行管理（如 PlayerData、Inventory 等）
- 运行时状态通过 SaveService 持久化

## 8. 配置加载流程

```
loadConfig(configName)
├── 已加载 → 直接 resolve
├── 正在加载 → 返回已有的 Promise
├── 未加载
│   ├── loadFromBundle(configName)
│   │   ├── 成功 → 继续
│   │   └── 失败 → reject，记录 error 日志
│   ├── parseConfig(json)
│   ├── validateConfig(configName, data)
│   │   ├── 校验通过 → 继续
│   │   └── 校验失败
│   │       ├── 开发版 → reject，阻止启动
│   │       └── 发布版 → 记录日志，继续
│   ├── buildIndex(configName, data)
│   ├── 存入 configs
│   └── resolve
└── 返回 Promise
```

## 9. 后续扩展：表格导出流程

当项目规模增长时，可接入 CSV/Excel → JSON 的导出流程：

1. 策划在 Excel 中编辑配置表
2. 导出工具将 Excel 转换为 JSON（校验格式和引用）
3. JSON 文件放入对应 Bundle 的 resources/config/ 目录
4. ConfigService 加载 JSON 文件

导出工具需求：
- 支持 Excel 多 Sheet（每个 Sheet 对应一个配置）
- 自动生成 TypeScript 类型定义
- 校验引用完整性
- 支持版本号管理

## 10. 实现注意事项

1. **配置 ID 稳定**，不要依赖数组下标访问配置项
2. **配置表与运行时状态分离**，不直接修改原始配置对象
3. **复杂表格可在后续接入 CSV/Excel → JSON 的导出流程**
4. **配置加载失败时**，关键配置阻止启动，非关键配置降级运行
5. **配置 Schema 在代码中定义**，与配置 JSON 文件分离，便于版本管理
