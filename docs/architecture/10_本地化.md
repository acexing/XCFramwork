## 1. 模块职责

- 语言切换与文本表查询
- 缺失 key 的开发期告警
- 数字、日期和复数格式统一
- 不把可见文本硬编码在业务脚本中
- 首发可先支持中文，保留英文扩展路径

---

## 2. 接口定义

```typescript
export interface ILocalizationService {
  getText(key: string, params?: Record<string, string | number>): string;
  getLanguage(): LanguageCode;
  setLanguage(lang: LanguageCode): Promise<void>;
  getSupportedLanguages(): LanguageCode[];
  hasKey(key: string): boolean;
  onLanguageChanged(handler: (lang: LanguageCode) => void): void;
  offLanguageChanged(handler: (lang: LanguageCode) => void): void;
}

export type LanguageCode = 'zh' | 'en';
```

## 3. 类结构设计

```
LocalizationService
├── private currentLanguage: LanguageCode         ← 当前语言
├── private textTables: Map<LanguageCode, Map<string, string>> ← 各语言文本表
├── private supportedLanguages: LanguageCode[]    ← 支持的语言列表

├── getText(key, params?): string

│
├── private loadLanguageTable(lang): Promise<void>

```

## 4. 文本表格式

### 4.1 JSON 格式

```json
{
  "common": {
    "ok": "确定",
    "cancel": "取消",
    "confirm": "确认",
    "close": "关闭"
  },
  "menu": {
    "start_game": "开始游戏",
    "settings": "设置",
    "exit": "退出"
  },
  "dialog": {
    "no_currency": "货币不足",
    "save_success": "保存成功",
    "save_failed": "保存失败"
  }
}
```

### 4.2 Key 命名规则

- 使用 `group.key` 格式，如 `common.ok`、`menu.start_game`
- group 名使用 snake_case
- key 名使用 snake_case
- key 在文本表中集中定义，不在代码中硬编码

### 4.3 Key 常量定义

```typescript
// core/interfaces/LocalizationKeys.ts
export const L10N_KEYS = {
  CommonOk: 'common.ok',
  CommonCancel: 'common.cancel',
  MenuStartGame: 'menu.start_game',
  MenuSettings: 'menu.settings',
  DialogNoCurrency: 'dialog.no_currency',
} as const;
```

## 5. 参数化文本

### 5.1 模板格式

```json
{
  "dialog": {
    "currency_changed": "货币从 {oldValue} 变为 {newValue}",
    "level_unlocked": "关卡 {levelId} 已解锁",
    "items_collected": "已收集 {count} 个物品"
  }
}
```

### 5.2 使用方式

```typescript
const text = localizationService.getText('dialog.currency_changed', {
  oldValue: 100,
  newValue: 200,
});
// 结果："货币从 100 变为 200"
```

### 5.3 格式化规则

- 使用 `{paramName}` 占位符
- 参数名在模板中必须存在，缺失时保留原始占位符并记录 warn 日志
- 数字参数自动转换为字符串

## 6. 语言切换流程

```
setLanguage(lang)
├── lang == currentLanguage → 直接 resolve
├── 检查是否已加载该语言文本表
│   ├── 已加载 → 继续
│   └── 未加载 → loadLanguageTable(lang)
│       ├── 成功 → 继续
│       └── 失败 → reject，记录 error 日志
├── currentLanguage = lang
├── 保存语言设置到 SaveService
├── notifyLanguageChanged()
│   └── 通知所有订阅者（UI组件刷新文本）
└── resolve
```

### 6.1 UI 刷新机制

- 语言切换后，所有显示文本的 UI 组件需要刷新
- 通过 EventBus 发送 `GameEvent.UILanguageChanged` 事件
- BaseView 可监听该事件，自动刷新绑定的文本
- 也可通过 `onLanguageChanged` 直接订阅 LocalizationService

---

## 7. 缺失 Key 处理

| 环境 | 行为 |
|------|------|
| 开发版 | 返回 `[MISSING: key]`，打印 warn 日志，记录到 missingKeyWarnings |
| 发布版 | 返回 key 本身（如 `common.ok`），不打印日志 |

- missingKeyWarnings 避免同一 key 重复告警刷屏
- DebugPanel 可展示所有缺失 key 列表

## 8. 数字与日期格式

### 8.1 数字格式

```typescript
// 中文环境：1,234,567
// 英文环境：1,234,567
// 大数字缩写：1.2M, 3.5K（按语言配置）
```

- 数字格式化方法在 LocalizationService 中提供
- 大数字缩写规则按语言配置

### 8.2 日期格式

- 使用时间戳存储，显示时按语言格式化
- 中文：2026年10月10日
- 英文：Oct 10, 2026

## 9. 资源加载

### 9.1 文本表存放位置

- 中文文本表：`bundles/core/resources/config/localization_zh.json`
- 英文文本表：`bundles/core/resources/config/localization_en.json`
- 文本表在核心 Bundle 中，启动时加载

### 9.2 加载策略

- 启动时加载当前语言的文本表
- 切换语言时按需加载目标语言文本表
- 已加载的文本表缓存在内存中，不重复加载

---

## 10. 实现注意事项

1. **不把可见文本硬编码在业务脚本中**，所有文本通过 LocalizationService 获取
2. **首发可先支持中文**，保留英文扩展路径
3. **缺失 key 的开发期告警**，发布版静默降级
4. **语言切换后 UI 自动刷新**，通过事件机制通知所有组件
5. **文本表 key 集中定义**，使用常量对象管理，禁止散落字符串
