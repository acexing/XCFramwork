## 1. 模块职责

- 语言切换与文本表查询
- 缺失 key 的开发期告警
- 数字、日期和复数格式统一
- 不把可见文本硬编码在业务脚本中
- 首发可先支持中文，保留英文扩展路径
- **多语言适配场景全覆盖**：文本、资源、UI、配置、平台
- **语言回退链**：目标语言 → 默认语言 → key 本身
- **多语言测试支持**：伪本地化、覆盖率检查

## 2. 多语言适配场景总览

### 2.1 适配维度矩阵

| 适配维度 | 说明 | 适配方式 | 优先级 |
|---------|------|---------|--------|
| UI 文本 | 按钮、标签、弹窗、提示等所有可见文字 | 文本表 + LocalizationService | P0（首发必须） |
| 配置文本 | 物品名称、关卡名称、成就描述等配置中的文本 | 配置表多语言字段 + 运行时查询 | P0（首发必须） |
| 数字格式 | 千分位分隔、大数字缩写、货币符号 | LocalizationService 格式化方法 | P1 |
| 日期格式 | 年月日顺序、分隔符 | LocalizationService 格式化方法 | P1 |
| 图片资源 | 含文字的图片（教程图、背景图等） | 多语言资源目录 + 按语言加载 | P2（按需） |
| 音频资源 | 语音旁白、含语言信息的音效 | 多语言音频目录 + 按语言加载 | P2（按需） |
| 字体 | 不同语言的字体回退（中文→英文字体兼容） | 字体配置表 + 按语言选择 | P1 |
| 复数形式 | 英文单复数、其他语言复数规则 | ICU MessageFormat 复数规则 | P2（英文必须） |
| 文本方向 | RTL（阿拉伯语、希伯来语）布局 | UI 布局镜像 + 文本方向标记 | P3（非首发） |
| 平台语言检测 | 跟随系统语言或用户手动选择 | PlatformAdapter.getSystemLanguage() | P0 |

### 2.2 适配场景详细说明

#### 场景 A：UI 文本适配

**问题**：UI 中所有 Label/RichText 组件的文本内容需要根据当前语言动态显示。

**方案对比**：

| 方案 | 说明 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|---------|
| 手动调用 getText | 每个组件在 onOpen/onShow 中手动调用 `l10n.getText(key)` | 灵活，可处理复杂逻辑 | 代码冗余，容易遗漏 | 动态生成文本、参数化文本 |
| L10nLabel 组件 | 自定义 Label 子类，绑定 key，自动刷新 | 声明式，零代码，自动响应语言切换 | 需要创建自定义组件 | 静态文本（按钮、标题等） |
| 装饰器绑定 | 使用 @property 标记需要本地化的字段 | 编辑器可视化绑定 | Cocos 装饰器限制较多 | 不推荐 |

**推荐方案**：**L10nLabel 组件 + 手动 getText 并行使用**

- 静态文本（按钮文字、标题、固定标签）使用 `L10nLabel` 组件，在编辑器中绑定 key
- 动态文本（参数化文本、运行时生成）使用 `getText()` 手动调用
- 语言切换时 `L10nLabel` 自动刷新，手动调用的文本通过 `UILanguageChanged` 事件刷新

#### 场景 B：配置文本适配

**问题**：配置表中的物品名称、关卡名称等需要多语言。例如 `items.json` 中 `name` 字段不能只存中文。

**方案对比**：

| 方案 | 说明 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|---------|
| 配置表存储 key | 配置表中 `name` 字段存 l10n key（如 `item.coin.name`） | 配置与文本完全分离，扩展性强 | 查询多一层间接，配置可读性降低 | 大规模配置、需要多语言 |
| 配置表多语言字段 | 配置表中存 `name_zh`、`name_en` | 直观，查询快 | 字段膨胀，新增语言需改表结构 | 小规模配置、语言数固定 |
| 配置表存默认语言 + key | 配置表中 `name` 存默认语言文本，`nameKey` 存 l10n key | 兼顾可读性和扩展性 | 两个字段需保持同步 | 过渡方案 |

**推荐方案**：**配置表存储 key**

- 配置表中 `name`/`description` 字段存储 l10n key（如 `items.item_001.name`）
- 文本表中定义对应翻译
- ConfigService 加载配置后，业务代码通过 `l10n.getText(itemConfig.name)` 获取当前语言文本
- 配置表保持语言无关，新增语言无需修改配置

#### 场景 C：图片资源适配

**问题**：部分图片包含文字（教程截图、活动 banner），需要按语言提供不同版本。

**方案**：**多语言资源目录 + 按语言加载**

```
bundles/core/resources/
├── images/
│   ├── tutorial_zh.png    ← 中文版教程图
│   ├── tutorial_en.png    ← 英文版教程图
│   └── tutorial_default.png ← 默认版（无文字或通用版）
```

- AssetPaths 中定义多语言资源路径模板：`images/tutorial_{lang}`
- 加载时先尝试当前语言版本，不存在则回退到 default 版本
- 纯装饰性图片（不含文字）不需要多语言版本

#### 场景 D：音频资源适配

**问题**：语音旁白、含语言信息的音效需要按语言提供不同版本。

**方案**：**多语言音频目录 + 按语言加载**

```
bundles/core/resources/
├── audio/
│   ├── voice/
│   │   ├── story_intro_zh.mp3
│   │   ├── story_intro_en.mp3
│   │   └── story_intro_default.mp3
│   └── sfx/
│       ├── button_click.mp3  ← 音效不含语言信息，无需多语言
```

- 旁白音频按语言提供，音效通常不需要
- AudioManager.playMusic/playSfx 可接受语言参数，自动选择对应语言资源
- 回退策略：当前语言 → 默认语言 → 无音频

#### 场景 E：字体适配

**问题**：不同语言可能需要不同字体。中文字体通常体积大，英文字体小且丰富。

**方案**：**字体配置表 + 按语言选择**

```json
// config/font_config.json
{
  "fonts": [
    {
      "id": "default_font",
      "zh": "fonts/SourceHanSans",
      "en": "fonts/Roboto-Regular",
      "default": "fonts/SourceHanSans"
    },
    {
      "id": "title_font",
      "zh": "fonts/SourceHanSans-Bold",
      "en": "fonts/Roboto-Bold",
      "default": "fonts/SourceHanSans-Bold"
    }
  ]
}
```

- 启动时加载字体配置，按当前语言选择对应字体
- Label 组件引用字体 ID，而非直接引用字体资源
- 语言切换时刷新所有 Label 的字体

#### 场景 F：复数形式适配

**问题**：英文中 "1 item" vs "2 items"，其他语言有更复杂的复数规则。

**方案**：**ICU MessageFormat 子集**

```json
{
  "inventory": {
    "items_count": "{count, plural, =0 {没有物品} =1 {1个物品} other {#个物品}}",
    "en_items_count": "{count, plural, =0 {No items} =1 {1 item} other {# items}}"
  }
}
```

- 支持 `=0`、`=1`、`other` 三种复数形式（覆盖中英文需求）
- `#` 表示当前数字值
- 中文通常不需要复数形式（"0个物品"、"1个物品"、"3个物品"），但英文必须区分
- 复数规则在文本表中定义，`getText` 自动解析

#### 场景 G：文本方向适配（RTL）

**问题**：阿拉伯语、希伯来语等从右向左书写，UI 布局需要镜像。

**方案**：**文本方向标记 + 布局镜像**

- LanguageCode 扩展 `direction` 属性：`'ltr' | 'rtl'`
- RTL 语言切换时，UI 布局自动镜像（左右翻转）
- Label 组件设置 `horizontalAlign` 为 RIGHT
- **首发不支持 RTL**，保留扩展接口

#### 场景 H：平台语言检测

**问题**：首次启动时应跟随系统语言，用户手动选择后记住偏好。

**方案**：**平台 Adapter 提供系统语言 + SaveService 存储用户偏好**

```
首次启动
├── PlatformAdapter.getSystemLanguage() → 获取系统语言
├── 如果系统语言在 supportedLanguages 中 → 使用系统语言
├── 如果系统语言不在 supportedLanguages 中 → 使用默认语言（zh）
└── 保存到 SaveService（slot: 'settings', key: 'language'）

后续启动
├── SaveService.load('settings') → 读取用户语言偏好
├── 有偏好 → 使用偏好语言
└── 无偏好 → 跟随系统语言（同首次启动）

用户手动切换
├── LocalizationService.setLanguage(lang)
├── 保存到 SaveService
└── 下次启动自动使用
```

## 3. 接口定义

```typescript
export type LanguageCode = 'zh' | 'en';

export interface LanguageInfo {
  code: LanguageCode;
  displayName: string;
  direction: 'ltr' | 'rtl';
  fontId: string;
}

export interface ILocalizationService {
  init(): Promise<void>;
  getText(key: string, params?: Record<string, string | number>): string;
  getLanguage(): LanguageCode;
  setLanguage(lang: LanguageCode): Promise<void>;
  getSupportedLanguages(): LanguageInfo[];
  hasKey(key: string): boolean;
  onLanguageChanged(handler: (lang: LanguageCode) => void): void;
  offLanguageChanged(handler: (lang: LanguageCode) => void): void;

  formatNumber(value: number, options?: NumberFormatOptions): string;
  formatDate(timestamp: number, options?: DateFormatOptions): string;
  getLocalizedAssetPath(basePath: string, extension: string): string;
  getFontId(): string;
}

export interface NumberFormatOptions {
  useGrouping?: boolean;
  abbreviate?: boolean;
}

export interface DateFormatOptions {
  showTime?: boolean;
  showYear?: boolean;
}
```

### 3.1 接口扩展说明

相比 v1.0，新增以下方法：

| 方法 | 说明 | 适配场景 |
|------|------|---------|
| `init()` | 初始化，加载默认语言文本表和字体配置 | 启动流程 |
| `formatNumber(value, options)` | 数字格式化（千分位、大数字缩写） | 场景 A |
| `formatDate(timestamp, options)` | 日期格式化（按语言习惯） | 场景 A |
| `getLocalizedAssetPath(basePath, ext)` | 获取多语言资源路径（带回退） | 场景 C/D |
| `getFontId()` | 获取当前语言的字体 ID | 场景 E |
| `getSupportedLanguages()` 返回 `LanguageInfo[]` | 包含语言方向、字体等元信息 | 场景 G |

## 5. 文本表格式

### 5.1 JSON 格式

```json
{
  "common": {
    "ok": "确定",
    "cancel": "取消",
    "confirm": "确认",
    "close": "关闭"
  },
  "menu": {
    "start_game": "开始游戏",
    "settings": "设置",
    "exit": "退出"
  },
  "dialog": {
    "no_currency": "货币不足",
    "save_success": "保存成功",
    "save_failed": "保存失败"
  },
  "items": {
    "item_001": {
      "name": "金币",
      "description": "通用货币，可用于购买商品"
    },
    "item_002": {
      "name": "宝石",
      "description": "稀有货币，用于特殊购买"
    }
  },
  "levels": {
    "level_001": {
      "name": "第一关",
      "description": "新手教程关卡"
    }
  }
}
```

### 5.2 嵌套 Key 访问

文本表支持嵌套结构，key 使用 `.` 分隔层级：

```typescript
l10n.getText('items.item_001.name'); // → "金币"
l10n.getText('levels.level_001.description'); // → "新手教程关卡"
```

### 5.3 Key 命名规则

- 使用 `group.key` 或 `group.subgroup.key` 格式
- group 名使用 snake_case
- key 名使用 snake_case
- 配置文本 key 格式：`{configName}.{itemId}.{fieldName}`
- key 在文本表中集中定义，不在代码中硬编码

### 5.4 Key 常量定义

```typescript
export const L10N_KEYS = {

  CommonConfirm: 'common.confirm',

  MenuSettings: 'menu.settings',
  MenuExit: 'menu.exit',
  DialogNoCurrency: 'dialog.no_currency',
  DialogSaveSuccess: 'dialog.save_success',
  DialogSaveFailed: 'dialog.save_failed',
} as const;
```

## 6. 参数化文本与复数

### 6.1 模板格式

```json
{
  "dialog": {
    "currency_changed": "货币从 {oldValue} 变为 {newValue}",
    "level_unlocked": "关卡 {levelId} 已解锁",
    "items_collected": "{count, plural, =0 {没有收集到物品} =1 {收集了1个物品} other {收集了#个物品}}"
  }
}
```

### 6.2 使用方式

```typescript
// 简单参数
l10n.getText('dialog.currency_changed', { oldValue: 100, newValue: 200 });
// → "货币从 100 变为 200"

// 复数形式
l10n.getText('dialog.items_collected', { count: 0 });
// → "没有收集到物品"
l10n.getText('dialog.items_collected', { count: 1 });
// → "收集了1个物品"
l10n.getText('dialog.items_collected', { count: 5 });
// → "收集了5个物品"
```

### 6.3 格式化规则

- 使用 `{paramName}` 占位符（简单参数）
- 使用 `{paramName, plural, ...}` 占位符（复数形式）
- 支持 `=0`、`=1`、`other` 三种复数分类
- `#` 在复数模板中表示当前数字值
- 参数名在模板中必须存在，缺失时保留原始占位符并记录 warn 日志
- 数字参数自动转换为字符串

## 7. 语言切换流程

```
setLanguage(lang)
├── lang == currentLanguage → 直接 resolve
├── 检查是否已加载该语言文本表
│   ├── 已加载 → 继续
│   └── 未加载 → loadLanguageTable(lang)
│       ├── 成功 → 继续
│       └── 失败 → reject，记录 error 日志
├── currentLanguage = lang
├── saveLanguagePreference(lang)
│   └── 通过 SaveService 保存到 settings 槽位
├── notifyLanguageChanged()
│   ├── 通过 EventBus 发送 GAME_EVENTS.UI_LANGUAGE_CHANGED
│   └── 通知所有 onLanguageChanged 订阅者
└── resolve
```

### 7.1 UI 刷新机制

语言切换后，所有显示文本的 UI 组件需要刷新。提供两种刷新路径：

**路径 1：EventBus 事件（推荐）**

- LocalizationService.init 时通过 EventBus 发送 `GAME_EVENTS.UI_LANGUAGE_CHANGED`
- BaseView 可在 `onOpen` 中订阅该事件，在回调中刷新文本
- BaseView.onDestroy 自动取消订阅（已有机制）

```typescript
// BaseView 子类示例
protected onOpen(): void {
  this.bindEvent(GAME_EVENTS.UI_LANGUAGE_CHANGED, this.onLanguageChanged);
}

private onLanguageChanged(): void {
  this.titleLabel.string = l10n.getText(L10N_KEYS.MenuStartGame);
}
```

**路径 2：L10nLabel 组件（静态文本推荐）**

- 自定义 Label 子类组件，绑定 l10n key
- 语言切换时自动刷新，无需手动代码
- 适合编辑器中可视化配置的静态文本

### 7.2 L10nLabel 组件设计

```typescript
@ccclass('L10nLabel')
export class L10nLabel extends Label {
  @property({ tooltip: '本地化 Key，如 common.ok' })
  l10nKey: string = '';

  @property({ tooltip: '参数 JSON，如 {"count": 5}' })
  l10nParams: string = '';

  protected onLoad(): void {
    this.refreshText();
    // 监听语言切换事件
    ServiceRegistry.get<IEventBus>(SERVICE_TOKENS.EVENT_BUS)
      .on(GAME_EVENTS.UI_LANGUAGE_CHANGED, this.onLanguageChanged, this);
  }

  protected onDestroy(): void {
    ServiceRegistry.get<IEventBus>(SERVICE_TOKENS.EVENT_BUS)
      .off(GAME_EVENTS.UI_LANGUAGE_CHANGED, this.onLanguageChanged, this);
  }

  public refreshText(): void {
    if (!this.l10nKey) {
      return;
    }
    const l10n = ServiceRegistry.get<ILocalizationService>(SERVICE_TOKENS.LOCALIZATION_SERVICE);
    let params: Record<string, string | number> | undefined;
    if (this.l10nParams) {
      try {
        params = JSON.parse(this.l10nParams);
      } catch {
        params = undefined;
      }
    }
    this.string = l10n.getText(this.l10nKey, params);
  }

  public setL10nKey(key: string, params?: Record<string, string | number>): void {
    this.l10nKey = key;
    if (params) {
      this.l10nParams = JSON.stringify(params);
    }
    this.refreshText();
  }

  private onLanguageChanged(): void {
    this.refreshText();
  }
}
```

## 8. 语言回退链

### 8.1 回退规则

```
getText(key)
├── 当前语言文本表有 key → 返回当前语言文本
├── 回退语言文本表有 key → 返回回退语言文本，记录 debug 日志
├── 开发版 → 返回 [MISSING: key]，记录 warn 日志
└── 发布版 → 返回 key 本身
```

- **回退语言**默认为 `zh`（中文），可在 LocalizationService 构造时配置
- 回退到回退语言时记录 debug 日志（非 warn，因为这是预期行为）
- 完全缺失时才触发 missingKey 告警

### 8.2 多语言扩展时的回退链

当支持更多语言时（如日语 `ja`、韩语 `ko`），回退链可配置为：

```
ja → zh → key 本身
ko → zh → key 本身
en → zh → key 本身
```

或更精细的回退：

```
ja → zh → en → key 本身
```

回退链在 `LanguageInfo` 中配置：

```typescript
interface LanguageInfo {
  code: LanguageCode;
  displayName: string;
  direction: 'ltr' | 'rtl';
  fontId: string;
  fallback?: LanguageCode;  // 该语言的回退语言
}
```

## 9. 缺失 Key 处理

| 环境 | 行为 |
|------|------|
| 开发版 | 返回 `[MISSING: key]`，打印 warn 日志，记录到 missingKeyWarnings |
| 发布版 | 返回 key 本身（如 `common.ok`），不打印日志 |

- missingKeyWarnings 避免同一 key 重复告警刷屏
- DebugPanel 可展示所有缺失 key 列表
- 提供工具脚本扫描代码中所有 `getText()` 调用的 key，与文本表交叉比对

## 10. 数字与日期格式

### 10.1 数字格式

```typescript
// 中文环境
l10n.formatNumber(1234567); // → "1,234,567"
```

## 16. 多语言测试

### 16.1 伪本地化测试

伪本地化（Pseudo-localization）是一种自动化测试方法，无需真实翻译即可检测多语言适配问题：

- **文本扩展**：将所有文本字符替换为更长的伪翻译（如 "确定" → "[确定!!!"），检测 UI 是否能容纳更长的文本
- **特殊字符**：插入特殊字符检测编码问题
- **缺失 key 检测**：所有 getText 调用返回 `[PSEUDO: key]`，快速发现遗漏的硬编码文本

```typescript
// 伪本地化模式
const PSEUDO_LOCALIZATION = false; // 开发版可开启

if (PSEUDO_LOCALIZATION) {
  l10n.getText = (key) => `[PSEUDO: ${key}]`;
}
```

### 16.2 覆盖率检查工具

提供脚本扫描代码中所有 `getText()` 调用的 key，与文本表交叉比对：

```
工具输出示例：
  ✓ common.ok — zh ✓, en ✓
  ✓ menu.start_game — zh ✓, en ✓
  ✗ dialog.new_feature — zh ✗ (缺失), en ✗ (缺失)
  ⚠ items.item_001.name — zh ✓, en ✗ (缺失，将回退到 zh)
```

### 16.3 测试清单

| 测试项 | 说明 | 验收标准 |
|--------|------|---------|
| 语言切换 | 切换语言后所有 UI 文本刷新 | 无残留旧语言文本 |
| 回退链 | 英文缺失 key 回退到中文 | 显示中文而非 [MISSING] |
| 参数化文本 | 参数正确替换 | 无残留 {paramName} |
| 复数形式 | 英文单复数正确 | 1 item / 2 items |
| 数字格式 | 大数字缩写正确 | 1.2M / 123.5万 |
| 日期格式 | 各语言日期格式正确 | 2026年10月10日 / Oct 10, 2026 |
| 多语言资源 | 图片/音频按语言加载 | 加载对应语言版本 |
| 字体切换 | 语言切换后字体正确 | 中文字体/英文字体 |
| 系统语言检测 | 首次启动跟随系统语言 | 正确检测并选择 |
| 语言偏好持久化 | 重启后保持用户选择 | SaveService 读写正常 |
| 配置文本 | 配置中 name 字段多语言 | 显示当前语言翻译 |
| 硬编码检测 | 无直接硬编码可见文本 | 伪本地化无遗漏 |

## 17. 实现注意事项

1. **不把可见文本硬编码在业务脚本中**，所有文本通过 LocalizationService 获取
2. **首发可先支持中文**，保留英文扩展路径
3. **缺失 key 的开发期告警**，发布版静默降级
4. **语言切换后 UI 自动刷新**，通过事件机制通知所有组件
5. **文本表 key 集中定义**，使用常量对象管理，禁止散落字符串
6. **配置表文本字段存 l10n key**，不存具体语言文本，保证配置语言无关
7. **多语言资源按需加载**，不含文字的图片/音效不需要多语言版本
8. **字体按语言选择**，中文字体体积大，英文可使用更轻量字体
9. **回退链保证可用性**，目标语言缺失时回退到默认语言，而非显示错误
10. **伪本地化测试**，开发阶段用伪翻译检测 UI 适配问题和硬编码遗漏
