## 1. TimerManager

### 1.1 模块职责

- 统一管理延迟任务、循环任务、暂停/恢复和取消
- 页面/场景销毁时按 owner 清理对应任务
- 对倒计时使用单一时间源，避免多个组件各自累计产生误差

### 1.2 接口定义

```typescript
export interface ITimerManager {
  delay(owner: unknown, callback: () => void, ms: number): TimerHandle;
  interval(owner: unknown, callback: () => void, ms: number): TimerHandle;
  countdown(owner: unknown, callback: (remaining: number) => void, totalMs: number, tickMs?: number): TimerHandle;
  cancel(handle: TimerHandle): void;
  cancelByOwner(owner: unknown): void;
  pause(handle: TimerHandle): void;
  resume(handle: TimerHandle): void;
  pauseByOwner(owner: unknown): void;
  resumeByOwner(owner: unknown): void;
  getActiveCount(): number;
}

export interface TimerHandle {
  id: number;
  owner: unknown;
  type: 'delay' | 'interval' | 'countdown';
  paused: boolean;
}
```

### 1.3 类结构设计

```
TimerManager
├── private timers: Map<number, TimerRecord>     ← 所有定时器记录
├── private ownerMap: Map<unknown, number[]>     ← owner → 定时器ID映射
├── private nextId: number                       ← 下一个定时器ID
├── private tickCallback: () => void             ← 引擎帧回调
│
├── delay(owner, callback, ms): TimerHandle
├── interval(owner, callback, ms): TimerHandle
├── countdown(owner, callback, totalMs, tickMs?): TimerHandle
├── cancel(handle): void
├── cancelByOwner(owner): void
├── pause(handle): void
├── resume(handle): void
├── pauseByOwner(owner): void
├── resumeByOwner(owner): void
├── getActiveCount(): number
│
├── private addTimer(record): TimerHandle
├── private removeTimer(id): void
├── private onTick(dt: number): void             ← 每帧更新定时器
└── private clearAll(): void
```

**TimerRecord 结构：**
```typescript
interface TimerRecord {
  id: number;
  owner: unknown;
  type: 'delay' | 'interval' | 'countdown';
  callback: Function;
  intervalMs: number;     // interval/countdown 的间隔
  remainingMs: number;    // 剩余时间
  totalMs: number;        // countdown 的总时间
  paused: boolean;
  lastTickTime: number;   // 上次触发时间
}
```

### 1.4 使用示例

```typescript
// 延迟执行
const handle = timerManager.delay(this, () => {
  console.log('3秒后执行');
}, 3000);

// 循环执行
const intervalHandle = timerManager.interval(this, () => {
  console.log('每秒执行');
}, 1000);

// 倒计时
const countdownHandle = timerManager.countdown(this, (remaining) => {
  this.label.string = `${Math.ceil(remaining / 1000)}s`;
}, 60000, 1000);

// 页面销毁时清理
onDestroy() {
  timerManager.cancelByOwner(this);
}
```

### 1.5 设计要点

- **单一时间源**：所有定时器由 `director.on(Director.EVENT_BEFORE_UPDATE)` 驱动，不使用 `setInterval`/`setTimeout`
- **owner 绑定**：每个定时器必须指定 owner，便于按 owner 批量清理
- **暂停/恢复**：暂停时记录剩余时间，恢复时继续倒计时
- **场景切换**：SceneService 在 afterLeave 钩子中对离开场景的组件调用 cancelByOwner

## 2. PoolManager

### 2.1 模块职责

- 对高频短生命周期对象使用对象池
- 池对象必须有重置逻辑，回收时清理事件、动画、定时器和临时状态
- 不为低频对象盲目引入对象池

### 2.2 接口定义

```typescript
export interface IPoolManager {
  register<T>(poolName: string, createFn: () => T, resetFn: (obj: T) => void, preloadCount?: number): void;
  get<T>(poolName: string): T;
  release<T>(poolName: string, obj: T): void;
  releaseAll(poolName: string): void;
  getPoolInfo(poolName: string): PoolInfo;
  clearAll(): void;
}

export interface PoolInfo {
  name: string;
  poolSize: number;       // 当前池中可用对象数
  activeCount: number;    // 当前借出的对象数
  totalCreated: number;   // 累计创建对象数
}
```

### 2.3 类结构设计

```
PoolManager
├── private pools: Map<string, PoolRecord>       ← 所有对象池
│
├── register<T>(poolName, createFn, resetFn, preloadCount?): void
├── get<T>(poolName): T
├── release<T>(poolName, obj): T
├── releaseAll(poolName): void
├── getPoolInfo(poolName): PoolInfo
├── clearAll(): void
│
├── private ensurePool(poolName): PoolRecord
└── private preload(poolName, count): void
```

**PoolRecord 结构：**
```typescript
interface PoolRecord {
  name: string;
  createFn: () => unknown;
  resetFn: (obj: unknown) => void;
  available: unknown[];    // 可用对象列表
  active: Set<unknown>;    // 借出的对象集合
  totalCreated: number;
}
```

### 2.4 适用场景

| 场景 | 是否使用对象池 | 原因 |
|------|--------------|------|
| 飘字提示（伤害数字、获得物品） | 是 | 高频创建销毁 |
| 粒子容器 | 是 | 高频创建销毁 |
| 重复 UI 列表项 | 是 | 列表滚动时频繁创建销毁 |
| 弹窗 Prefab | 否 | 低频，UIManager 的 cache 机制已处理 |
| 场景中的固定物体 | 否 | 生命周期长，不需要池化 |
| 一次性特效 | 视频率而定 | 频繁则池化，偶尔则不池化 |

### 2.5 使用示例

```typescript
// 注册对象池
poolManager.register(
  'damageText',
  () => instantiate(damageTextPrefab),
  (obj: Node) => {
    obj.setPosition(0, 0, 0);
    obj.getComponent(DamageText).reset();
  },
  10 // 预创建10个
);

// 获取对象
const text = poolManager.get<Node>('damageText');
text.parent = this.node;
text.getComponent(DamageText).show(100);

// 回收对象
poolManager.release('damageText', text);
```

### 2.6 设计要点

- **池对象必须有重置逻辑**：resetFn 在回收时调用，清理事件、动画、定时器和临时状态
- **不为低频对象盲目引入对象池**：对象池会增加生命周期复杂度
- **预创建数量合理**：避免预创建过多占用内存，也避免运行时频繁创建
- **借出对象追踪**：active 集合记录借出的对象，便于调试和 releaseAll
- **Node 池化注意**：回收 Node 时必须从父节点移除（`node.parent = null`）

## 3. 两个模块的共同原则

1. **owner 绑定**：TimerManager 通过 owner 清理定时器，PoolManager 不需要 owner（由调用方负责 release）
2. **开发版统计**：两个模块在开发版都提供统计信息，便于 DebugPanel 展示
3. **引擎帧驱动**：TimerManager 使用引擎帧回调，不使用浏览器原生定时器
4. **资源清理**：组件销毁时必须清理对应的定时器和池对象
