## 1. 模块职责

- 统一事件命名与类型定义
- 支持 `on`、`once`、`off`、`emit`
- 订阅者在组件销毁或页面关闭时解除订阅
- 开发版可打印事件名和触发次数

---

## 2. 接口定义

```typescript
export interface IEventBus {
  on<T>(event: string, handler: EventHandler<T>, target?: unknown): void;
  once<T>(event: string, handler: EventHandler<T>, target?: unknown): void;
  off(event: string, handler?: EventHandler, target?: unknown): void;
  offByTarget(target: unknown): void;
  emit<T>(event: string, data?: T): void;
  hasListener(event: string): boolean;
  clear(): void;
}

export type EventHandler<T = unknown> = (data: T) => void;
```

## 3. 类结构设计

```
EventBus
├── private listeners: Map<string, ListenerRecord[]>    ← 事件监听记录
├── private targetMap: Map<unknown, string[]>           ← target → 事件名映射（便于 offByTarget）
├── private emitCount: Map<string, number>              ← 事件触发次数（开发版统计）
│
├── on<T>(event, handler, target?): void
├── once<T>(event, handler, target?): void
├── off(event, handler?, target?): void
├── offByTarget(target): void
├── emit<T>(event, data?): void
├── hasListener(event): boolean
├── clear(): void
│
├── private addListener(event, handler, target, once): void
├── private removeListener(event, handler, target): void
└── private logEmit(event): void  ← 开发版日志
```

**ListenerRecord 结构：**
```typescript
interface ListenerRecord {
  handler: EventHandler;
  target: unknown;
  once: boolean;
}
```

## 4. 事件命名规范

### 4.1 事件名集中定义

```typescript
// core/events/GameEvents.ts
export const GameEvent = {
  // 货币相关
  CurrencyChanged: 'CurrencyChanged',
  CurrencyNotEnough: 'CurrencyNotEnough',
  // 存档相关
  SaveCompleted: 'SaveCompleted',
  SaveFailed: 'SaveFailed',
  // 场景相关
  SceneBeforeEnter: 'SceneBeforeEnter',
  SceneAfterEnter: 'SceneAfterEnter',
  // UI相关
  UILanguageChanged: 'UILanguageChanged',
  // 玩法相关
  LevelCompleted: 'LevelCompleted',
  ItemUnlocked: 'ItemUnlocked',
} as const;
```

### 4.2 命名规则

- 使用 PascalCase 命名
- 事件名描述"发生了什么"，如 `CurrencyChanged`、`LevelCompleted`
- 不使用 `On` 前缀（如 `OnCurrencyChanged`），因为订阅动作本身就是 on
- 事件名在 `GameEvent` 常量对象中集中定义，禁止散落字符串

## 6. 生命周期绑定

### 6.1 组件自动清理

```typescript
// 推荐方式：在 BaseView 或 Component 基类中提供便捷绑定
export abstract class BaseView extends Component {
  private eventBindings: Array<{ event: string; handler: EventHandler; target: unknown }> = [];

  protected bindEvent<T>(event: string, handler: EventHandler<T>): void {
    this.eventBindings.push({ event, handler, target: this });
    EventBus.on(event, handler, this);
  }

  protected onClose(): void {
    // 自动清理所有事件订阅
    for (const binding of this.eventBindings) {
      EventBus.off(binding.event, binding.handler, binding.target);
    }
    this.eventBindings.length = 0;
  }
}
```

### 6.2 offByTarget 使用场景

- 页面/组件销毁时调用 `EventBus.offByTarget(this)` 清理所有订阅
- SceneService 在 afterLeave 钩子中可对离开场景的组件批量清理
- UIManager 在 close 视图时自动调用 offByTarget

## 7. 使用规则

| 规则 | 说明 | 违反后果 |
|------|------|---------|
| E1 | 事件名集中定义 | 字符串散落，难以追踪和维护 |
| E2 | 事件参数使用明确的 TypeScript 类型 | 类型不安全，运行时错误 |
| E3 | 禁止匿名订阅后无法取消 | 事件泄漏，内存增长 |
| E4 | 不把所有函数调用改成事件 | 数据流混乱，难以追踪因果关系 |
| E5 | 需要结果的操作使用服务方法 | 事件无返回值，无法获取操作结果 |
| E6 | 组件销毁时必须解除订阅 | 事件泄漏，已销毁组件被回调导致报错 |

## 8. 开发版调试支持

### 8.1 事件日志

- 开发版每次 emit 时打印事件名和触发次数
- 可配置过滤：只关注特定事件
- 发布版关闭所有事件日志

### 8.2 事件统计

```typescript
// 开发版可通过 DebugPanel 查看
interface EventStats {
  totalEvents: number;
  totalEmits: number;
  eventDetails: Array<{
    name: string;
    listenerCount: number;
    emitCount: number;
  }>;
}
```

### 8.3 泄漏检测

- 开发版定期检查：是否存在 target 已被销毁但仍有订阅的情况
- 检测到泄漏时打印 warn 日志，包含事件名和 target 信息

---

## 9. 错误处理

| 场景 | 处理方式 |
|------|---------|
| handler 执行抛出异常 | 记录 error 日志（包含事件名和错误信息），不影响其他 handler |
| emit 未注册的事件 | 记录 debug 日志（可能正常，如无订阅者的通知） |
| off 不存在的订阅 | 记录 debug 日志，不执行任何操作 |
| 重复 on 同一事件同一 handler | 记录 warn 日志，忽略重复注册 |

## 10. 实现注意事项

1. **事件只用于解耦通知**，有返回值、需要确认结果的操作应使用明确的方法调用
2. **订阅者生命周期绑定**：推荐使用 BaseView.bindEvent 便捷方法，确保自动清理
3. **once 的语义**：触发一次后自动移除，不需要手动 off
4. **emit 是同步的**：所有 handler 在当前调用栈中执行，不要在 handler 中做耗时操作
5. **禁止跨场景传递事件数据中的 Node 引用**：场景切换后 Node 可能已销毁
