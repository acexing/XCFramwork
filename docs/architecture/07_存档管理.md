## 1. 模块职责

- 自动存档与手动存档入口
- 多槽位存档（如项目需要）
- 存档版本号与迁移函数
- 读取失败、版本不兼容、数据损坏时提供安全回退
- 存档写入临时数据并验证成功后再更新正式存档
- 设置数据与进度数据分开保存
- 支持导入/导出存档（可选）

## 4. 存档结构设计

### 4.1 存档信封（SaveEnvelope）

```typescript
interface SaveEnvelope<T> {
  schemaVersion: number;  // 存档数据结构版本
  savedAt: number;        // 保存时间戳
  checksum?: string;      // 数据校验和
  data: T;                // 实际存档数据
}
```

### 4.2 存档槽位划分

| 槽位 | 内容 | 存储方式 | 说明 |
|------|------|---------|------|
| settings | 游戏设置（音量、语言等） | localStorage | 轻量数据，快速读写 |
| progress | 主进度存档 | 平台 Adapter | 重要数据，需要校验和迁移 |
| autosave | 自动存档 | 平台 Adapter | 定期自动保存 |
| manual_1 | 手动存档槽1 | 平台 Adapter | 用户手动保存 |
| manual_2 | 手动存档槽2 | 平台 Adapter | 用户手动保存 |
| manual_3 | 手动存档槽3 | 平台 Adapter | 用户手动保存 |

### 4.3 设置数据与进度数据分离

```
settings（轻量、频繁读写）
├── audio_settings
├── language
├── display_settings
└── control_settings

progress（重要、需要校验）
├── story_progress
├── unlocked_items
├── currency
├── achievements
└── level_records
```

## 5. 存档写入流程（安全写入）

```
save<T>(slot, data)
│
├── 1. 构建 SaveEnvelope
│   ├── schemaVersion = currentSchemaVersion
│   ├── savedAt = Date.now()
│   ├── checksum = computeChecksum(data)
│   └── data = 序列化后的数据
│
├── 2. 序列化为 JSON 字符串
│
├── 3. 写入临时位置（如 slot + '.tmp'）
│   └── 失败 → reject，记录 error 日志
│
├── 4. 验证临时位置读取是否一致
│   ├── 一致 → 继续
│   └── 不一致 → 删除临时文件，reject
│
├── 5. 替换正式存档
│   ├── 删除旧正式存档
│   ├── 临时文件重命名为正式存档名
│   └── 失败 → 尝试恢复旧存档，记录 error 日志
│
├── 6. 更新内存缓存
│
└── 7. resolve
```

## 6. 存档读取流程

```
load<T>(slot)
│
├── 1. 检查内存缓存
│   ├── 有缓存 → 返回缓存数据
│   └── 无缓存 → 继续
│
├── 2. 从存储读取原始数据
│   ├── 成功 → 继续
│   ├── 不存在 → resolve(null)
│   └── 读取失败 → onReadFailed
│       ├── 记录 error 日志
│       ├── 尝试读取备份（如有）
│       ├── 备份可用 → 使用备份数据
│       └── 备份不可用 → resolve(null)，记录 warn 日志
│
├── 3. 反序列化 JSON
│   ├── 成功 → 继续
│   └── 失败（数据损坏） → resolve(null)，记录 error 日志
│
├── 4. 校验 checksum
│   ├── 一致 → 继续
│   └── 不一致 → 记录 warn 日志，仍尝试使用数据（降级）
│
├── 5. 版本迁移
│   ├── schemaVersion == current → 直接使用
│   ├── schemaVersion < current → 依次执行迁移函数
│   │   ├── 迁移成功 → 使用迁移后数据
│   │   └── 迁移失败 → resolve(null)，记录 error 日志
│   └── schemaVersion > current → 记录 warn 日志，尝试使用（前向兼容）
│
├── 6. 更新内存缓存
│
└── 7. resolve(data)
```

## 7. 版本迁移机制

### 7.1 迁移注册

```typescript
// 每次存档结构变更时注册迁移函数
saveService.registerMigration(1, (oldData) => {
  // v1 → v2: 添加新字段，转换旧字段格式
  return {
    ...oldData,
    newField: defaultValue,
    renamedField: oldData.oldFieldName,
  };
});

saveService.registerMigration(2, (oldData) => {
  // v2 → v3: 其他结构变更
  return { ...oldData, v3Field: computeFromV2(oldData) };
});
```

### 7.2 迁移执行规则

- 迁移函数按版本号顺序执行（v1→v2, v2→v3, ...）
- 每个迁移函数只处理一个版本升级
- 迁移失败时：保留原始数据备份，存档标记为需要人工修复
- 迁移完成后更新 schemaVersion 并重新保存

## 8. 存储适配器接口

```typescript
export interface IStorageAdapter {
  read(key: string): Promise<string | null>;
  write(key: string, data: string): Promise<void>;
  delete(key: string): Promise<void>;
  exists(key: string): Promise<boolean>;
  listKeys(prefix: string): Promise<string[]>;
}
```

**平台实现：**
- **DesktopAdapter**：使用 `fs`（Node.js）或 Cocos 文件系统 API
- **AndroidAdapter**：使用 Cocos 文件系统 API，存档目录通过平台 Adapter 提供
- **WebAdapter**（开发版）：使用 localStorage

## 9. 自动存档策略

- 定期自动存档：每 60 秒检查一次，如有数据变更则保存
- 关键节点自动存档：关卡完成、获得物品、剧情节点等
- 应用切后台时自动存档（Android `EVENT_HIDE`）
- 自动存档使用独立槽位，不影响手动存档

---

## 10. 错误处理

| 场景 | 处理方式 |
|------|---------|
| 读取失败 | 尝试备份，备份不可用则返回 null |
| 数据损坏（JSON解析失败） | 返回 null，记录 error 日志 |
| checksum 不一致 | 记录 warn 日志，尝试使用数据（降级） |
| 版本不兼容 | 尝试迁移，迁移失败则返回 null |
| 写入失败 | 记录 error 日志，reject Promise |
| 空间不足 | 记录 error 日志，提示用户清理空间 |

## 11. 实现注意事项

1. **`localStorage` 适合设置、轻量数据**，不应作为所有原生平台上大型关键存档的唯一方案
2. **Steam 云存档**需要明确文件路径、同步冲突策略与用户关闭云同步时的行为
3. **存档目录通过平台 Adapter 提供**，不硬编码安装目录为可写目录
4. **Android 测试**：卸载、升级安装、低存储空间和应用被系统回收后的恢复行为
5. **导入/导出**：导出为 Base64 编码的 JSON 字符串，导入时校验格式和版本
